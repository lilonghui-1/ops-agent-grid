1. 登录与认证

打开浏览器访问 Ops-Agent-Grid Web 管理平台。

1

访问平台：浏览器输入 http://<服务器IP>:5173（开发）或 http://<域名>（生产）。

2

输入账号密码：默认管理员 admin / admin123。

3

登录成功：跳转到仪表盘页面，JWT Token 保存在 localStorage，30 分钟内免重新登录。

首次登录后请立即修改默认密码！在系统设置中可修改。

3.3 Web 终端

在浏览器内直接操作目标服务器的 SSH 终端，无需安装本地 SSH 客户端。

1

进入终端页面：左侧导航点击「Web 终端」

2

选择服务器：从下拉列表中选择目标服务器

3

点击连接：xterm.js 终端打开，显示连接信息

4

执行命令：直接在终端中输入命令，支持所有交互式操作

5

断开连接：点击「断开」按钮，或关闭浏览器页面

Web 终端的操作会被审计日志记录，请谨慎执行高风险命令。

4. 日志查询

支持两种日志查询方式：SSH 直连检索 和 Loki 日志平台查询。

4.1 SSH 日志检索

通过 SSH 直接在目标服务器上执行日志查询命令，适合快速排查。

1

选择目标服务器

2

输入日志文件路径，如 /var/log/nginx/error.log

3

设置过滤条件：关键词、时间范围、行数

4

点击「查询」按钮，日志结果实时展示在页面中

4.2 Loki 日志查询

对接 Grafana Loki 日志平台，支持 LogQL 查询语法。

参数说明示例
LogQLLoki 查询语句{job="nginx"} |= "error"
时间范围查询的时间窗口最近 1 小时
结果限制最大返回行数1000

常用 LogQL 示例

# 查询所有 Nginx 错误日志
{job="nginx"} |= "error"

# 按主机筛选
{host="192.168.1.10", job="application"}

# 多关键词组合（AND/OR）
{job="application"} |= "timeout" or "connection refused"

# 正则匹配
{job="nginx"} |~ "\\d{3} Error"

# 统计错误速率
sum(rate({job="application"} |= "error" [5m])) by (host)

# 格式化提取字段
{job="nginx"} | json | line_format "{{.status}} {{.request}}"

4.3 实时日志流

点击「实时跟踪」按钮，通过 WebSocket 实时推送新日志，类似于 tail -f 效果。点击「停止」可结束跟踪。

5. 应用服务管理

管理目标服务器上的应用服务（systemd 服务 / Windows 服务）。

5.1 服务列表

列名说明
服务名称systemd / Windows 服务名
显示名称服务描述
状态running / stopped / failed
启动类型auto / manual / disabled
操作启动 / 停止 / 重启

5.2 服务操作

  • 启动：执行 systemctl start <service> 或 Start-Service
  • 停止：执行 systemctl stop <service> 或 Stop-Service
  • 重启：执行 systemctl restart <service> 或 Restart-Service
服务重启属于高风险操作。若 config.yaml 中 approval.require_for_risky 为 true，重启操作需要审批通过后才能执行。

支持对服务器上的配置文件进行在线编辑、分类管理和版本回滚。

6.1 配置分类

分类说明示例

6.2 编辑配置文件

7. AI 对话

通过自然语言与运维 Agent 交互，自动调度工具完成运维任务。

7.1 对话界面

  • 模型选择：可在 GPT-4 / Qwen-Plus / DeepSeek-Chat 等模型间切换
  • 消息历史：支持上下文连续对话
  • Markdown 渲染：Agent 回复支持 Markdown 格式（表格、代码块、列表等）
  • 工具调用可视化：展示 Agent 调用的工具及返回结果

7.2 常用对话示例

7.3 Agent 工作流

AI 对话后台由 Coordinator 协调器处理，工作流程：

  1. 意图理解：LLM 解析用户输入，识别任务类型
  2. 任务分解：将复杂任务拆解为子任务
  3. 专家路由：将子任务分发给对应 Specialist（SRE/网络/数据库/计算）
  4. 工具调用：Specialist 选择并调用合适工具执行
  5. 审批门控：高风险操作暂停，等待人工审批
  6. 结果汇总：Coordinator 收集各专家结果，生成最终报告

8. 告警管理

8.1 告警规则

支持三种告警规则类型：

类型触发条件示例
阈值规则指标超过设定阈值CPU > 80% 持续 5 分钟
日志关键词日志中出现指定关键词nginx 日志出现 "500 Internal Server Error"
PromQL 规则PromQL 查询结果满足条件rate(http_requests_total{status="500"}[5m]) > 10

创建告警规则

1

在「告警管理」页面点击「新建规则」

2

选择规则类型，填写规则名称和触发条件

3

设置告警级别：Info / Warning / Critical / Fatal

4

选择通知通道（钉钉/企微/Slack 等）

5

保存规则，系统按 evaluation_interval 定期评估

告警 Webhook

支持接收 Alertmanager 发送的告警通知。配置 URL：

POST http://<server>:8000/api/alerts/webhook
Authorization: Bearer <ALERT_WEBHOOK_TOKEN>
Content-Type: application/json

{
  "alerts": [
    {
      "status": "firing",
      "labels": {
        "alertname": "HighCPU",
        "severity": "warning",
        "instance": "192.168.1.10"
      },
      "annotations": {
        "summary": "CPU usage above 80%",
        "description": "192.168.1.10 CPU at 92.3%"
      }
    }
  ]
}

收到告警后，系统自动创建事件并触发 IncidentInvestigator 进行根因分析。

8.2 事件中心

事件中心展示所有告警触发的事件，包含完整生命周期管理。

9. 审批管理

高风险操作（如服务重启、配置变更）需经过人工审批后方可执行。

9.1 审批流程

  1. Agent 执行高风险操作时，自动创建审批请求
  2. 审批请求发送到 IM 通道通知审批人
  3. 审批人在 Web 界面或 IM 消息中审批
  4. 审批通过 → 继续执行；审批拒绝 → 中止操作
  5. 超时（默认 24h）自动过期，操作中止

9.2 审批列表

列名说明
请求 ID审批请求唯一标识
操作描述待执行的操作详情
风险等级Low / Medium / High
发起人触发操作的 Agent
目标服务器操作影响的服务器
状态Pending / Approved / Rejected / Expired
创建时间审批请求创建时间
过期时间自动过期时间（创建时间 + 24h）

9.3 审批操作

  • 批准：点击「批准」按钮，Agent 自动继续执行操作
  • 拒绝：点击「拒绝」按钮并填写理由，Agent 中止操作
  • 批量审批：选中多个请求，一键批量批准或拒绝

10. 拓扑图

可视化展示服务之间的依赖关系和调用链路。

10.1 拓扑视图

  • 节点：代表服务器/服务/数据库，颜色表示健康状态（绿=正常/黄=告警/红=故障）
  • 连线：表示服务间调用依赖，箭头表示调用方向
  • 交互：点击节点查看详情，拖拽调整布局，滚轮缩放
  • 爆炸半径：选中故障节点时，高亮显示受影响的所有下游服务

10.2 拓扑构建

系统通过以下方式自动构建拓扑：

  • SSH 采集服务器上的进程和网络连接信息
  • K8s Service / Endpoint 关系（如配置了 K8s）
  • 手工标注的服务依赖关系

14. 自愈规则配置

自愈规则定义在 config/rules.yaml，支持条件触发和审批控制。

14.1 规则结构

heal_rules:
  - name: "restart_nginx"               # 规则名称
    condition: "nginx_status == 'stopped'"  # 触发条件
    actions:
      - tool: "service_control"         # 调用的工具
        params:
          service_name: "nginx"
          action: "restart"
        confirm_required: false          # 是否需要人工确认
    description: "Nginx 停止时自动重启"

14.2 内置规则列表

规则名触发条件操作需确认
restart_nginxNginx 停止/错误率>10%重启 Nginx否
restart_application应用进程不存在重启应用否
clean_journal_logs磁盘使用率>85%清理 3 天前系统日志否
clean_apt_cache磁盘使用率>90%清理包管理器缓存是
clean_old_logs磁盘使用率>90%清理 7 天前压缩日志是
kill_long_queriesMySQL 长查询>10 且>10分钟终止慢查询是
flush_redisRedis 内存>95%调整淘汰策略是
restart_windows_serviceWindows 自动服务停止重启服务否
clean_windows_tempWindows 磁盘>90%清理临时文件否
restart_iisIIS 应用池停止/错误率>10%重启 IIS否

14.3 自定义规则

在 config/rules.yaml 中添加自定义规则：

heal_rules:
  # 自定义规则：磁盘满时清理 Docker 日志
  - name: "clean_docker_logs"
    condition: "disk_usage_percent > 92"
    actions:
      - tool: "ssh_execute"
        params:
          command: "sudo truncate -s 0 /var/lib/docker/containers/*/*-json.log"
        confirm_required: true
    description: "磁盘使用率超过92%时清理 Docker 容器日志（需确认）"

14.4 审批与自愈的关系

当 confirm_required: true 时，自愈操作不会立即执行，而是创建审批请求。 审批通过后，Agent 自动继续执行。若 24 小时内未审批，请求自动过期。
